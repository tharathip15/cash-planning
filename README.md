# Profess — Next.js

## เริ่มใช้งาน
Node.js 20.9 ขึ้นไป
```bash
npm install
npm run dev
```
เปิด http://localhost:3000

Production:
```bash
npm run build
npm start
```

## ขอบเขต
ย้ายระบบล่าสุดเข้า Next.js App Router โดยคงโมดูล JavaScript ที่แก้ DOM เดิมไว้ใน Client Component ไม่ใช่การเขียนทุกโมดูลใหม่เป็น React hooks และไม่ใช้ iframe ไม่ได้เปลี่ยนเว็บที่เผยแพร่อยู่

มีภาพรวม ปฏิทินรายละเอียดรายวัน ตารางรับ/จ่าย แผนรับเงิน/ลูกหนี้ popup ตาม policy ค้นหาตามหัวตาราง เลือกช่วงวัน และ Import/Export Excel พร้อมสี

## โครงสร้างและจุดเชื่อมระบบ
- app/page.jsx และ app/layout.jsx: หน้าเริ่มต้นและ metadata
- app/globals.css: รูปแบบเดิม
- components/CashWorkspace.jsx: โหลดโมดูลตามลำดับ
- components/screen.json: markup คงที่จาก source ห้ามแทนด้วย HTML จากผู้ใช้
- public/app.js: fetch data.json และ save()/localStorage เป็นจุดเปลี่ยนไปใช้ API ฐานข้อมูล; ฟอร์ม receipt/payment ยืนยันยอดจริง
- public/grid.js: ตารางรับ/จ่าย
- public/calendar-detail.js: รายละเอียดปฏิทิน
- public/ar.js: syncAllArPlans(), arPaid(), arOutstanding() เชื่อมบิล แผนรับ และยอดรับจริง
- public/ar-sheet.js: arCommitSheet() ตรวจและ commit ลูกหนี้
- public/ar-notice.js: popup แจ้งเตือนเมื่อเปิดเว็บ
- public/search.js: ค้นหาแต่ละหัวตาราง
- public/excel-io.js: ioBuildPlan()/ioCommit() ตรวจและนำเข้า Excel รวมส่งออกพร้อมสี
- public/data.json: ข้อมูลเริ่มต้นเดิม
- public/vendor/: SheetJS และ JSZip พร้อม license

## การเชื่อมระบบจริง
ยังไม่มี API routes, database, login, สิทธิ์ AR/AP, Odoo, ธนาคาร หรือการส่งหนังสือจริง ควรเพิ่ม server validation, authentication และ audit log ก่อนใช้ร่วมกันในองค์กร การแจ้งเตือนเมื่อปิดเว็บต้องมี server scheduler เพิ่ม

ข้อมูลที่คีย์อยู่ localStorage แต่ละเบราว์เซอร์และ origin จึงไม่ย้ายจากเว็บเดิมมาที่ localhost อัตโนมัติ ให้ Export จากเว็บเดิมแล้ว Import ที่เว็บใหม่ ไม่ได้บรรจุ localStorage ของผู้ใช้ลงในชุดนี้

public/data.json มีข้อมูลตั้งต้นเดิม หากเผยแพร่สาธารณะให้ตรวจหรือเปลี่ยนไฟล์นี้ก่อน

## การพัฒนาต่อ
โมดูลเดิมใช้ globals และ listeners หน้า root นี้ต้อง mount ครั้งเดียว หากเพิ่ม Next client navigation เข้าออกหน้านี้ ต้องเพิ่ม cleanup/module lifecycle ก่อน เมื่อแก้ bootstrap หรือ scripts ให้รีเฟรชเต็มหน้า

เก็บ package-lock.json หลังติดตั้งเพื่อให้ทีมใช้เวอร์ชันตรงกัน ดู VALIDATION.md สำหรับผลตรวจจริง

## อัปเดตรายงานอัตโนมัติ
ในเมนูรายงาน กด “เลือกไฟล์และอัปเดตอัตโนมัติ” เลือก .xlsx/.xls ที่มีชีตยอดขาย-ค้างรายเดือน และรายชื่อลูกค้าและเครดิต ระบบจับคู่หัวตาราง ตรวจข้อมูล และแทนชุดรายงานทั้งสองพร้อมกัน เก็บไว้ localStorage และย้อนกลับชุดก่อนได้ หากอ่านสูตรไม่ได้ให้เปิด Excel คำนวณและบันทึกก่อนนำเข้า

โมดูล public/reports-import.js ใช้กฎจับคู่ในเครื่อง ไม่ได้เรียก LLM ไม่ดึงไฟล์เองตามเวลา ไม่แชร์ข้อมูลข้ามเครื่อง และไม่อัปเดตยอดแผนเงินสด การตั้งเวลาดึงข้อมูลต้องพัฒนา backend และเชื่อมแหล่งไฟล์เพิ่มเติม

## สร้างรายงานจากรายงานต้นทาง (ล่าสุด)
เมนูรายงาน → นำเข้ารายงานต้นทาง → เลือกยอดขายรายบิล / ลูกหนี้คงค้างรายบิล / ข้อมูลลูกค้าและเครดิต และรับชำระตัดบิล (ไม่บังคับ) เลือกชีต แถวหัวตาราง และจับคู่คอลัมน์ ระบุปี พ.ศ. และวันที่ snapshot ตรวจตัวอย่างก่อนกดอัปเดตสองรายงาน มี Template 4 ชีตให้ดาวน์โหลดในหน้าเว็บ

- ประมวลผล public/reports-raw.js ฝั่งเบราว์เซอร์ ไม่ใช้ AI ภายนอก
- จับคู่บริษัท + รหัสลูกค้า + เลขบิล; ยอดขายอาจมีหลายบรรทัดต่อบิลและจะรวมกัน ลูกหนี้ต้องหนึ่งแถวต่อบิล
- ยอดขายใช้ยอดรวม VAT; ใบลดหนี้ใช้ค่าติดลบ
- ยอดค้างรายเดือนนับเฉพาะปีเอกสารที่เลือก; เครดิตรวมยอดค้างทุกปีและแจ้งยอดนอกปี
- วันรับจริงเฉลี่ย = ผลรวม (ยอดรับตัดบิล × วันจากวันที่บิลถึงวันรับ) ÷ ยอดรับรวมจากไฟล์ที่แนบ ไม่ใช่ค่าเครดิตเทอมและไม่คาดเดาจากยอดค้าง
- ไม่มีไฟล์รับชำระให้เว้นวันรับจริงว่าง; เครดิตว่างไม่แปลงเป็น 0
- ไม่แก้ข้อมูลแผนเงินสด/ลูกหนี้ติดตามอัตโนมัติ; ข้อมูลรายงานบันทึกเป็น localStorage snapshot พร้อมสำรองชุดก่อน
- ยังไม่เชื่อมแหล่งไฟล์ดึงเองตามเวลา/API/ฐานข้อมูลกลาง

## อัปเดตเฉพาะชุดและเชื่อมระบบ (ล่าสุด)
- หลังนำเข้าต้นทางครบครั้งแรก ระบบเก็บ rawSources ใน snapshot เดียวกัน ครั้งถัดไปเปลี่ยนเฉพาะไฟล์ยอดขาย/ลูกหนี้/รับชำระได้โดยใช้ชุดอื่นที่เก็บไว้ พร้อมแสดงวันที่ของแต่ละชุด
- เลือกอัปเดตทั้งสองรายงาน รายเดือนอย่างเดียว เครดิตอย่างเดียว หรือแผนรับ/ลูกหนี้อย่างเดียว ชีตสรุปที่เตรียมแล้วนำเข้าเพียงชีตเดียวได้และคงอีกชุดไว้
- แผนรับมีปุ่มดึงจากยอดขายรายบิล ใช้ไฟล์ยอดขายอย่างเดียวเตรียมร่างได้ แต่ถ้าไม่มีไฟล์คงค้างต้องตรวจยอดชำระก่อนใช้เอง หากมี snapshot คงค้าง จะเตรียมเฉพาะบิลที่จับคู่ได้และยังค้าง
- กลุ่มยอดขายหลายบรรทัดเป็นหนึ่งบิล จับคู่บริษัท+รหัสลูกค้า+เลขบิล เก็บยอดบิลเต็ม และแยกยอดตัดลดก่อนเริ่มระบบจากส่วนต่างยอดบิลกับยอดคงค้าง ไม่สร้างรายการรับจริงจากส่วนต่างนี้
- ข้ามบิลที่มีแล้ว ไม่เขียนทับวันนัด ประวัติติดตาม ยอดรับ หรือร่างที่ผู้ใช้คีย์ไว้; บิลไม่มีวันที่ส่ง/SO/SS/เครดิต/วันครบกำหนดต้องเติมก่อนบันทึก
- บันทึกร่างผ่านแผนรับแล้วใช้ syncAllArPlans เดิมเชื่อมรายการรับ ปฏิทิน และภาพรวม เงินเข้าจริงยังต้องยืนยันตามขั้นตอนเดิม
- รายงานที่สร้างจาก raw bills เก็บ cashLink ต่อรายงาน ยอดค้างจะลดด้วย actual receipts ที่ยืนยันและมี actualDate หลังวันที่ snapshot เท่านั้น ไม่หักรายการในวันเดียวกันซ้ำ ไม่หักแผนรับที่ยังไม่ยืนยัน ไม่แก้ยอดขายหรือเครดิตจากการรับเงิน
- นำเข้าเฉพาะรายงานเครดิตจะคง snapshot ของรายเดือนเดิมไว้ รวมถึงแหล่ง/วันที่/bill mapping ของรายเดือนเดิม ไม่ใช้ rawSources ชุดใหม่ย้อนแก้ snapshot เก่า
